# 13 — Decisions Addendum (changes vs. the original pack, with reasons)

Original documents remain the source of truth; these are the deliberate, evidence-based deviations found while implementing.

ADR-7 to ADR-11 were recorded during the first sandbox session and verified there. ADR-12 to ADR-19 were taken from the Windows agent's session log (M3–M5) and should be confirmed against the code when it is next reviewed.

- **ADR-7 Language/RTL switch without reload.** Expo's localization guide states runtime `I18nManager.forceRTL` does not work in Expo Go (it resets RTL prefs), which would break ADR-4 (Expo Go only). Implemented instead: `direction` style on the root `View` + `LocaleProvider` (expo-router) + our own `isRTL` from the resolved locale (never `I18nManager.isRTL`). Verified on react-native-web (tabs, alignment, chips mirror in ar and flip back in en). **Not yet verified on a physical phone.** Supersedes the "reload" sentence in docs/05.
- **ADR-8 Medusa scaffold flattened.** `create-medusa-app` (2.22.1) now generates a Turborepo (`backend/apps/backend`, optional Next.js storefront). Flattened to a single independent npm project at `apps/backend` (ADR-3). Template demo seeds (EUR apparel, Next.js store-policy migration) removed; replaced by `src/scripts/seed.ts` (ILS, 4 categories, 16 sample products, idempotent).
- **ADR-9 Routes live in `src/app/`.** The SDK 58 Expo template uses `src/app`, not `app/` (docs/01 tree). Same Expo Router rules; paths in docs map 1:1 under `src/`.
- **ADR-10 Bilingual catalog data.** Medusa has no per-locale product fields in this MVP. English lives in `title`/`description`; Arabic in `metadata.title_ar`, `description_ar`, `option_ar`, and categories' `metadata.name_ar`. The app picks by locale and falls back to English. Cheap, no extra module.
- **ADR-11 Local image URLs are absolute.** Medusa's local file provider stores `BACKEND_URL/static/...` at upload time. Set `BACKEND_URL` to the LAN IP **before** `npm run seed`, or re-seed after changing it (`.env.example` explains).
- **ADR-12 Server-authoritative totals in checkout** (AGENTS rule 12). The checkout screen displays Medusa's `total`, `subtotal` and `shipping_total`; it does not compute final totals locally. Selecting a shipping option first updates the Medusa cart, and the displayed total is the one Medusa returns. Browsing and the cart screen still show clearly labelled local **estimates** (ADR-1).
- **ADR-13 Local-first cart syncs at checkout start.** Unchanged from ADR-1 and confirmed in implementation: `khafif.cart.v1` (Zustand persist), merged by variant, quantities capped by stock, items sent to Medusa only when checkout begins. No offline order queue (ADR-2).
- **ADR-14 Calculated-price shipping options are not selectable.** Medusa can return options with `calculated` pricing that the app cannot price. They are shown disabled instead of displaying a misleading total. Flat-rate options (the seeded ones) work normally.
- **ADR-15 Payment provider resolved at runtime.** Checkout looks up the region's configured provider (`pp_system_default`, test only) instead of hard-coding it. No payment credentials are collected or stored (ADR-5).
- **ADR-16 Duplicate-order protection.** The submit button is locked while a request is in flight, `complete` is sent with an idempotency key, and re-loading the checkout does not add the shipping method a second time.
- **ADR-17 Confirmation screen carries no PII in the route.** The order screen is keyed by order id and shows the server-confirmed total; the customer's email is not placed in navigation params or URLs. The local cart is cleared only after a successful `complete`.
- **ADR-18 Guest checkout only until M7.** Checkout collects email, name, address and phone with zod validation; no login. A missing `region_id` is rejected with a clear error instead of passing `undefined` to the payment endpoint.
- **ADR-19 `@medusajs/types` is an explicit dependency of `apps/mobile`.** `@medusajs/js-sdk` references it as a dev dependency, so without it the SDK response types collapse to `any` and strict TypeScript fails. It is pinned to the same version as the backend (2.22.1) and must be listed in `docs/VERSIONS.md`.
- **Environment note (not a project decision).** On the owner's machine the project lives at `E:\Khafif-Application`, the shell used by the agent was Bash rather than PowerShell, and some file tools pointed at a non-existent `E:\Khafif`. Always pass the full project path explicitly. The first sandbox session verified against local PostgreSQL 16 because Docker was unavailable; `infra/docker-compose.yml` is provided but has not been executed anywhere yet.
